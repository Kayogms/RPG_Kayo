Paintball: Problema e Modelagem Bipartida
Redução formal para emparelhamento perfeito de tamanho N
🎯 Regras e Objetivo
  • Entrada: N jogadores (2 ≤ N ≤ 1.000) e M pares de visibilidade mútua (0 ≤ M ≤ 5.000).
  • Munição estrita: Cada jogador possui exatamente uma bola de tinta.
  • Condição de tiro: Só é possível atirar em quem se consegue enxergar (u ↔ v).
  • Alvo exclusivo: Cada jogador deve ser atingido exatamente uma vez.
  • Saída: Alvo de cada jogador 1 … N ou Impossible.
Propriedade Estrutural: O problema reduz-se a encontrar um Emparelhamento Perfeito em Grafo Bipartido (Bipartite Perfect Matching), saturando todos os vértices.
👥 A Dualidade de Papéis (2N Vértices)
Elemento Original Modelo Bipartido Duplicado
Jogador k Atirador Ak (quem atira) e Alvo Bk (quem recebe)
Vértices (V) |V| = 2N (conjuntos disjuntos A e B)
Visibilidade (u, v) Duas arestas direcionadas: Au → Bv e Av → Bu
Arestas (E) |E| = 2M conexões direcionadas de tiro
Classificação Grafo Bipartido, simples e não ponderado

📦 Reutilizadas sem Alteração (algs4)
  • algs4.graph.Graph:
    Instanciado com 2N vértices para armazenar a adjacência bipartida.
  • algs4.bag.Bag:
    Lista encadeada interna de cada vértice. A inserção em O(1) no início (LIFO) define a ordem de consulta dos alvos.
⚖️ Por que DepthFirstPaths não serviu?

A classe DepthFirstPaths usa marcação permanente para conectividade simples. O emparelhamento exige:

  • Marcação temporária (target) zerada a cada atirador;
  • Lógica de desalocação e realocação recursiva ao colidir com alvo ocupado.
⚙️ Implementação: KuhnMatcher
  • Classe dedicada: criada para implementar o Algoritmo de Kuhn com DFS sobre a estrutura Graph.
  • Estado global: match_para[t] mantém o emparelhamento construído.
  • Recursão: tenta realocar o ocupante atual antes de ceder o alvo para o novo atirador.
🚀 Versão Autocontida (main_submissao.py)

Para o juiz online Kattis, unificou-se o modelo em um único arquivo autônomo, substituindo Bag por listas nativas do Python e garantindo compatibilidade estrita sem dependências externas.

Algoritmo de Kuhn: Rastreamento no Exemplo C4
Simulação manual detalhada demonstrando o efeito cascata de desalocação

Instância Didática: N = 4 jogadores em ciclo (1-2, 2-3, 3-4, 4-1). Devido à inserção LIFO do Bag, a ordem de consulta de A1 é B4 e depois B2.

Passo Atirador Alvo Consultado Situação Decisão / Ação do Algoritmo Caminho Aumentante Emparelhamento Atual
1 A1 (Jog. 1) B4 (Jog. 4) Livre A1 assume B4 diretamente. A1 → B4 {A1 → B4}
2 A2 (Jog. 2) B3 (Jog. 3) Livre A2 assume B3 diretamente. A2 → B3 {A1 → B4, A2 → B3}
3 A3 (Jog. 3) B4 (Jog. 4) Ocupado por A1 Efeito Cascata: A3 pede para A1 mudar de alvo. A1 consulta B2, que está livre. A1 migra para B2. A3 assume B4. A3 → B4 → A1 → B2 {A1 → B2, A2 → B3, A3 → B4}
4 A4 (Jog. 4) B1 (Jog. 1) Livre A4 assume B1 diretamente. A4 → B1 {A1 → B2, A2 → B3, A3 → B4, A4 → B1}
Resultado Final: Jogador 1 atira no 2 | Jogador 2 no 3 | Jogador 3 no 4 | Jogador 4 no 1. Resposta: 2, 3, 4, 1 (perfeito e bijetor).

⏱️ Complexidade Assintótica
Operação Complexidade No Pior Caso (Kattis)
Construção do Grafo O(N + M) 2.000 + 10.000 passos
Algoritmo de Kuhn O(V · E) = O(NM) Limite teórico ≈ 107; na prática ≈ 0,07 s
Memória do Grafo O(N + M) < 2 MB de memória
Memória Auxiliar O(N) Arrays e pilha de chamadas
🛡️ RecursionError Prevenido

Lição herdada do T1: com N = 1000, cadeias lineares de deslocamento poderiam atingir o limite padrão de recursão do Python. Configurou-se preventivamente sys.setrecursionlimit(200000).
